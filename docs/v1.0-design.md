# cat-blog v1.0 设计记录

> 状态：设计已定稿（grilling 共 7 轮，2026-11-24）。
> 本文记录 v1.0 的全部设计决定，实现以本文为准；如需改动，先更新本文。

## 1. 目标

构建一个类似 [Bear Blog](https://bearblog.dev) 的简洁博客程序。

- **v1.0**：单人自部署。部署到服务器后，管理员登录后台，用 Markdown 编写首页、创建和管理页面（pages）与文章（blog posts）。
- **之后**：扩展为类似 Bear Blog 的多用户托管服务（SaaS）并收费。v1.0 的结构要为此预留空间，但不提前实现多用户功能。
- 不设计 logo，站点默认标题为颜文字 `ฅ^•ﻌ•^ฅ`。

## 2. 与 Bear Blog 的关系

Bear Blog 源码公开（Django 单体应用），但使用 **Bear Blog License 2.0**，禁止将其作为托管服务提供。cat-blog 计划做 SaaS，因此 **只借鉴设计思路，代码、模板、CSS 全部自行编写**。

借鉴的设计：

- 页面与文章共用一张表，用类型字段区分。
- 扁平 URL：`/{slug}/` 统一承载页面和文章，`/blog/` 为文章列表。
- 编辑器是一个纯文本框：头部写元数据，下面写 Markdown 正文。
- `{{ posts }}` 嵌入指令：在首页或页面中插入文章列表。
- 一份极简 CSS，用 CSS 变量和 `prefers-color-scheme` 支持暗色模式。

不借鉴（v1.0 不做）：子域名与自定义域名、付费、Discover 广场与点赞、访问统计、邮件订阅、媒体库。

## 3. 已确定的决定

| # | 主题 | 决定 |
|---|---|---|
| D1 | 语言与框架 | Rust。Web 框架 axum（tokio 运行时）。 |
| D2 | 数据库 | SQLite，通过 sqlx 访问，SQL 迁移放在 `migrations/`，启动时自动执行。sqlx 同时支持 Postgres，为 SaaS 迁移留路。 |
| D3 | 渲染方式 | 服务端渲染，模板用 askama（编译期检查，打包进二进制）。前端不用框架，只在编辑器里写少量原生 JS。 |
| D4 | Markdown | comrak（GFM：表格、脚注、任务列表、标题锚点）。 |
| D5 | HTML 清洗 | 从 v1.0 开始用 ammonia 白名单清洗渲染结果：去掉 `<script>`、`on*` 属性、`javascript:` 链接；保留 `<details>` 等常用标签，`<iframe>` 只允许白名单域名。 |
| D6 | 多租户预留 | 有 `users` 和 `blogs` 表，`posts` 带 `blog_id`，所有查询按 `blog_id` 过滤。v1.0 只有一个用户、一个博客；"当前请求属于哪个博客"集中在一个函数里解析，以后改为按域名查找。 |
| D7 | 编辑格式 | 首页、页面、文章都用 **YAML front matter + Markdown 正文**，在同一个纯文本框里编辑。 |
| D8 | URL 结构 | `/` 首页；`/blog/` 文章列表；`/{slug}/` 页面或文章；`/admin/` 后台。 |
| D9 | 页面与文章的区分 | 由后台的新建入口决定（Pages / Blog），数据库字段 `kind` 取 `page` 或 `post`，不写在 front matter 里。 |
| D10 | slug 规则 | 同一博客内全局唯一（页面和文章共用）；不能占用保留路径（`blog`、`admin`、`feed.xml`、`sitemap.xml`、`robots.txt`、`static` 等）；冲突时直接报错，不自动改名；支持 UTF-8，例如 `/我的第一篇文章/`；front matter 不写 `slug` 时由标题生成（具体规则见 D32）。 |
| D11 | 站点设置 | 写在首页的 front matter 里：`title`（默认 `ฅ^•ﻌ•^ฅ`）、`description`、`lang`、`timezone`（默认 `Asia/Singapore`）、`nav`（Markdown，默认 `[Home](/) [Blog](/blog/)`）。不设单独的设置页。 |
| D12 | 草稿与发布 | `draft: true` 表示草稿；`date` 写成未来时间即为定时发布。草稿和未到时间的文章不出现在列表、RSS、sitemap 中，访问时返回 404，登录的管理员可以预览。不写 `date` 时，以首次发布的时间作为发布日期。日期按站点时区解释。 |
| D13 | 账号结构 | 按账号系统设计（`users` 表、密码哈希、会话），但 v1.0 只有一个用户。 |
| D14 | 管理员账号来源 | 用户名和密码写死在 `.env` 中（`ADMIN_USERNAME`、`ADMIN_PASSWORD`），修改时编辑 `.env` 后重启。不提供网页注册，也不提供网页安装向导。启动时同步到 `users` 表：表中还没有用户就新建；用户名或密码不一致就更新，并清空所有会话。`.env` 存明文密码（文件权限 600），数据库只存哈希。后台不提供修改密码的页面。密码少于 12 位时拒绝启动。 |
| D15 | 登录安全 | 登录页填用户名和密码。同一 IP 输错 5 次锁定 15 分钟（记录在内存）。会话 cookie 设置 `HttpOnly`、`Secure`、`SameSite=Lax`，有效期 30 天；后台所有 POST 请求校验 CSRF token。 |
| D16 | 会话 | 存在数据库 `sessions` 表中，库里只存 token 的 SHA-256 哈希；退出登录时删除对应记录。 |
| D17 | 密码哈希 | argon2id。 |
| D18 | 用户与博客 | `blogs.user_id` 外键，结构上允许一个用户拥有多个博客，v1.0 只用一个；后台按"当前用户是否拥有该博客"鉴权。 |
| D19 | 不需要 SECRET_KEY | 会话和 CSRF token 都用操作系统的安全随机数生成，不需要额外的签名密钥。 |
| D20 | v1.0 范围（包含） | RSS（`/feed.xml`，RSS 2.0，最近 20 篇）；`sitemap.xml`、`robots.txt`；front matter 中的 `tags`，以及 `/blog/?tag=x` 筛选；编辑器预览（服务端渲染，在新标签页打开）；删除前确认，确认后直接从数据库删除；内置 CSS 并支持暗色模式；服务端代码高亮（输出 CSS class）；`{{ posts }}` 指令，支持 `limit`、`tag` 两个参数。 |
| D21 | v1.0 范围（不包含） | 图片上传（先用外部图床链接）、自定义 CSS、访问统计、邮件订阅、评论、导入导出、草稿分享链接。 |
| D22 | 部署 | 程序只监听 HTTP（默认 `127.0.0.1:3000`），HTTPS 交给 Caddy 或 Nginx。配置全部来自环境变量或 `.env`。提供 `Dockerfile`、systemd 服务文件和 Caddyfile 示例。备份只需复制数据库文件。 |
| D23 | 测试 | 单元测试覆盖 front matter 解析、slug 生成与冲突、HTML 清洗、草稿和定时发布的可见性；集成测试用内存 SQLite 跑通"登录 → 新建文章 → 公开访问 → 草稿返回 404 → 退出"的完整流程。模板和样式不写测试，改为截图检查。 |
| D24 | 产品名 | `cat-blog`（仓库 `zht7063/cat-blog`），同时作为 crate 名和可执行文件名。 |
| D25 | 代码组织 | 标准 Cargo workspace：`crates/core` 放纯逻辑（front matter、Markdown 渲染、HTML 清洗、slug、可见性规则），不依赖 Web 和数据库；`crates/server` 放数据库、认证、axum、模板和命令行入口，产出 `cat-blog` 可执行文件。顶层目录还有 `migrations/`、`templates/`、`static/`、`deploy/`、`docs/` 和 `.env.example`。 |
| D26 | 后台界面 | `/admin/` 顶部导航为"首页 \| Pages \| Blog \| 查看站点 \| 退出"。Pages 和 Blog 各有一个列表页，每行显示标题、日期和草稿或定时标记，上方有"新建"按钮。编辑页是一个全屏 textarea，新建时预填 front matter 模板；有"保存""预览""删除"三个按钮；支持 Ctrl/⌘+S 保存；有未保存改动时离开页面会提醒。解析出错时保留原文，并在页面顶部显示带行号的错误信息。 |
| D27 | 视觉风格 | 内容区最大宽度 720px；使用系统字体栈并包含中文字体，行高 1.7；页头放标题 `ฅ^•ﻌ•^ฅ` 和导航；页脚显示 `Powered by cat-blog ฅ^•ﻌ•^ฅ`；支持亮色和暗色两套主题，并提供**手动切换按钮**（具体行为见 D31）。 |
| D28 | 默认内容 | 首次启动时，首页显示一段欢迎文字和 `{{ posts limit:5 }}`；同时创建一篇示例草稿《Hello, cat-blog》，演示 front matter 的写法。 |
| D29 | 许可证 | AGPL-3.0。 |
| D30 | 工程配置 | Rust 2024 edition，用 `rust-toolchain.toml` 固定 stable 工具链；GitHub Actions 运行 `cargo fmt --check`、`cargo clippy -D warnings` 和 `cargo test`；启用 sqlx 离线模式，`.sqlx/` 提交到仓库。 |
| D31 | 主题切换 | 页头右侧放一个图标按钮，在亮色和暗色之间切换。用户没点过时跟随系统；点过后把选择存进 `localStorage`。`<head>` 里放内联脚本，渲染前就设置 `data-theme`，避免颜色闪烁。禁用 JS 时隐藏按钮，跟随系统。公开页面和后台共用。 |
| D32 | UTF-8 slug | 生成：标题先做 NFC 规范化，保留任何语言的字母和数字，ASCII 字母转小写，空格和标点替换为 `-` 并合并，去掉首尾 `-`（例：`我的 Rust 笔记！` → `我的-rust-笔记`）。手写的 slug 按同样规则规范化后写回 front matter。匹配：请求路径先做百分号解码，再按 NFC 和小写规范化后查库。最长 80 个字符（按字符计）。 |
| D33 | 渲染时机 | 保存时渲染 Markdown 并清洗，结果存在 `html` 列；`{{ posts }}` 在请求时展开。提供 `cat-blog rerender` 命令，用来在渲染规则升级后重新渲染全部内容。 |
| D34 | 日期格式 | 统一显示为 `2026-11-24`，按站点时区，只显示日期。自定义格式（`date_format`）以后再做。 |
| D35 | 界面语言 | 后台只做中文，文字集中在一处，便于以后国际化。公开页面中程序自带的文字跟随首页 `lang`，v1.0 提供 `zh` 和 `en` 两套，默认 `zh-CN`。 |
| D36 | Cookie 的 Secure 标记 | `BASE_URL` 以 `https://` 开头时加 `Secure`，以 `http://` 开头时不加，并在启动时打印警告日志，提醒生产环境使用 HTTPS。 |
| D37 | 文章列表 | `/blog/` 和 `?tag=x` 的结果都不分页，一次列出全部文章，每行只显示日期和标题。需要时再加 `?page=`。 |
| D38 | 客户端 IP | 用于登录限流，只存在内存中，不写入数据库或日志。`TRUSTED_PROXIES` 列出可信代理的 IP 段，默认 `127.0.0.1/32,::1/128`。直连地址不可信时，直接使用该地址并忽略 `X-Forwarded-For`；直连地址可信时，从 `X-Forwarded-For` 最右侧向左跳过可信地址，取第一个不可信地址作为客户端 IP；请求头缺失或格式错误时退回直连地址。Docker 部署示例中设置为 `172.16.0.0/12`；使用 CDN 时由部署者自行加入 CDN 的 IP 段。 |

## 4. 配置（环境变量 / `.env`）

| 变量 | 必需 | 默认值 | 说明 |
|---|---|---|---|
| `ADMIN_USERNAME` | 是 | — | 唯一管理员的用户名 |
| `ADMIN_PASSWORD` | 是 | — | 管理员密码，至少 12 位 |
| `DATABASE_PATH` | 否 | `./data/cat-blog.db` | SQLite 文件路径 |
| `BIND_ADDR` | 否 | `127.0.0.1:3000` | 监听地址 |
| `BASE_URL` | 是 | — | 站点公开地址，生成 RSS、sitemap 中的绝对链接时使用；以 `https://` 开头时 cookie 带 `Secure` |
| `TRUSTED_PROXIES` | 否 | `127.0.0.1/32,::1/128` | 可信反向代理的 IP 段，逗号分隔（见 D38） |

## 5. 数据模型（草案）

```sql
users    (id, username UNIQUE, password_hash, created_at, updated_at)
sessions (id, user_id → users, token_hash UNIQUE, created_at, expires_at)
blogs    (id, user_id → users, home_source, home_html, -- 首页原文和渲染结果
          title, description, lang, timezone, nav,     -- 从首页 front matter 解析出来的字段
          created_at, updated_at)
posts    (id, blog_id → blogs, kind ('page'|'post'), slug,
          source,                                      -- 原文（front matter + 正文）
          html,                                        -- 保存时渲染并清洗好的正文
          title, tags, draft, published_at,            -- 解析出的字段，用于查询和列表展示
          created_at, updated_at,
          UNIQUE (blog_id, slug))
```

原文按作者输入原样保存，编辑时原样还原；解析出的字段单独存列，用于查询和排序。

## 6. front matter 字段（草案）

**首页**：`title`、`description`、`lang`、`timezone`、`nav`。

**页面和文章**：`title`、`slug`、`date`、`draft`、`tags`（文章用）、`description`（用于 meta 和 RSS）。

遇到未知字段时报错，提示作者修改。
