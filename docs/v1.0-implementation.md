# cat-blog v1.0 实施文档

> 状态：待审阅（2026-11-24）。
> 本文说明按什么顺序、用哪些依赖、怎样验证来实现 [v1.0-spec.md](v1.0-spec.md)。设计上的问题以设计文档为准；本文只管\"怎么做\"。
> 标注\"可否决\"的是实施层面的默认选择，审阅者不同意时直接评论修改。

## 1. 原则

- 每个阶段结束时仓库都能编译、`cargo test` 全绿，CI 通过。
- 先写 `crates/core` 的纯逻辑和单元测试，再接数据库和 Web。core 里不出现 `sqlx`、`axum`、`tokio`。
- 所有 SQL 只写在 `crates/server/src/db/`（设计文档 §12）。
- 遇到设计文档没覆盖的问题，先改设计文档，再写代码（[v1.0-design.md](v1.0-design.md) 开头的约定）。

## 3. 依赖

| 用途 | crate | 说明 |
|---|---|---|
| Web | `axum`、`tokio`、`tower-http` | 请求体上限、超时、压缩、访问日志 |
| 数据库 | `sqlx`（features：`sqlite`、`runtime-tokio`、`macros`、`migrate`） | 编译期宏 + 离线模式（风险见设计文档 §12） |
| 模板 | `askama` | |
| Markdown | `comrak`（关掉默认 feature，只开 `syntect-fancy`） | 默认 feature 带命令行依赖和 onig C 库 |
| 清洗 | `ammonia`、`lol_html` | `lol_html` 只用来删掉 `src` 被清洗掉的 `<iframe>`（D54），ammonia 只能删属性 |
| YAML | `serde_yaml_ng`、`serde`（derive） | D50；只在 `frontmatter.rs` 使用 |
| 时间 | `jiff`（core 开启 `tzdb-bundle-always`） | 带 IANA 时区数据库，解析和格式化都靠它，不依赖系统 tzdata（可否决，备选 `chrono` + `chrono-tz`） |
| Unicode | `unicode-normalization` | NFC |
| 密码 | `argon2` | |
| 随机数与哈希 | `rand`（`OsRng`）、`sha2`、`base64`、`subtle` | `subtle` 用于常量时间比较 |
| 配置 | `dotenvy` | |
| JSON | `serde_json` | 只在 `db` 模块读写 `posts.tags`（D46） |
| 命令行 | `clap`（derive） | |
| 日志 | `tracing`、`tracing-subscriber`（`env-filter`） | D63 |
| 静态资源 | `rust-embed` | D60（可否决，备选 `include_bytes!`） |
| IP 段 | `ipnet` | D38 |
| RSS | 用 askama 模板直接输出 XML | 不引入 `rss` crate（可否决） |
| 测试 | `tokio` 测试运行时、`tower::ServiceExt::oneshot`、`insta`（快照，可选）、`tempfile` | HTTP 集成测试不起真实端口；启动流程的测试（阶段 2）运行真实进程，监听端口 0，验证退出码和 `.env` 加载；`tempfile` 给测试用的数据库和 `.env` 建临时目录 |

新增依赖前先在本表登记。

## 4. 阶段

每个阶段列出产出和完成条件。阶段内的顺序可以调整。

### 阶段 0：工程骨架

- Cargo workspace、两个 crate、`rust-toolchain.toml`、AGPL-3.0 的 `LICENSE`（D29）。
- 按 [conventions.md](conventions.md) 建立检查工具：`[workspace.lints]`、`clippy.toml`、`deny.toml`、`scripts/check.sh`、`scripts/check-arch.sh`、`.githooks/commit-msg`，以及 `crates/server/src/clock.rs` 的 `Clock`。
- `ci.yml` 运行 `scripts/check.sh`（fmt、`clippy --workspace --all-targets --locked`、test、`cargo sqlx prepare --check`、`cargo deny`、架构检查），设置 `SQLX_OFFLINE=true`（D30）。
- `server` 能启动，`GET /healthz` 返回 `ok`。

**完成条件**：CI 绿；每条新检查都手动造一次违规，确认它会报错并给出改法（conventions §2、§4.3），包括 conventions §4.2 末尾要验证的 sqlx 宏拦截。

### 阶段 1：core 纯逻辑

按依赖顺序：`slug` → `tags` → `date` → `frontmatter`（含写回） → `visibility` → `directive` → `sanitize` → `markdown`。

需要重点测的地方（D23 单元测试的具体内容）：

| 模块 | 必测用例 |
|---|---|
| slug | `我的 Rust 笔记！` → `我的-rust-笔记`；全角标点；NFD 输入；连续标点合并；全是标点 → 空；超 80 字符截断后不以 `-` 结尾；保留路径（含大小写变体 `Admin`、`Feed.XML`） |
| frontmatter | 未知字段报错且行号正确；类型错误；缺少结束 `---`；CRLF 输入；页面写 `tags` 报错；`tags: rust` 报错 |
| slug 写回 | 没写 slug 时插在 `title:` 后；已有 slug 只替换值；注释和其他行不动；`slug: 2024` 写回为 `slug: "2024"`；多行 slug 报错；写回后的原文再解析得到同一个 slug（幂等） |
| date | 三种写法；只写日期取站点时区 00:00；夏令时时区（如 `America/New_York`）的边界；非法时区报错 |
| published_at | 首次发布取 now；撤回再发布保留（D45）；写了 `date` 时以 `date` 为准 |
| visibility | 草稿、未来时间、`published_at` 为空、恰好等于 now |
| directive | 参数顺序；未知参数；行内和代码块中不展开（D55） |
| sanitize | `<script>`、`onclick`、`javascript:`、`data:` 链接被删；非白名单 iframe 整体删除；白名单 iframe 保留；checkbox 强制 `disabled`；作者写的 `<!--cat-blog:posts-->` 被删（不能伪造占位） |
| markdown | 表格、脚注、任务列表、标题锚点、高亮 class 都能通过清洗留下来；`<details>` 留下来 |

**完成条件**：上表用例全部有测试并通过；core 不依赖 Web 和数据库（`cargo tree -p cat-blog-core` 检查）。

### 阶段 2：数据库与启动

- `migrations/0001_init.sql`（设计文档 §6）；连接参数（D72）。
- `db` 模块：用户、会话、博客、内容的增删改查。
- 启动流程（设计文档 §4.1）：配置校验、迁移、管理员同步、默认内容、清理过期会话、优雅退出。
- 生成并提交 `.sqlx/`（`cargo sqlx prepare --workspace`）。CI 用离线数据编译。

**完成条件**：空目录首次启动后，库里有一个用户、一个博客、首页和示例草稿；改 `.env` 的密码后重启，旧会话被清空；密码少于 12 位时进程以非零状态码退出。

### 阶段 3：公开站点

- 路由（设计文档 §8.1）、地址规范化和 301（D58）、404 页（D61）。
- 请求时展开 `{{ posts }}` 占位。
- RSS、sitemap、robots；嵌入静态资源；安全响应头（D74）；请求体上限（D62）。
- 模板与 CSS：页头、页脚、720px 内容区、亮暗主题和切换按钮（D27、D31），高亮 CSS（D51）。

**完成条件**：集成测试覆盖：可见文章 200、草稿 404、未来文章 404、`/Foo` → 301 `/foo/`、百分号编码的中文 slug 能访问、RSS 只含可见文章且地址为绝对地址、`?tag=` 大小写不敏感。

### 阶段 4：后台

- 登录、退出、会话中间件、CSRF（D47）、限流（D48）、客户端 IP 解析（D38）。
- 首页、Pages、Blog 的列表和编辑页；保存、slug 写回、错误显示行号；删除确认页（D76）；预览（D56、D68）。
- `editor.js`：Ctrl/⌘+S、离开提醒。

**完成条件**：D23 的完整流程集成测试通过：登录 → 新建文章 → 公开访问 → 改成草稿后返回 404 → 退出。另有测试：缺 `_csrf` 的 POST 返回 403；登录页 `Origin` 不符返回 403；第 6 次登录（同一 IP、15 分钟内）返回 429；改标题后 URL 不变；保存冲突的 slug 返回 422 且原文保留。

### 阶段 5：命令与部署

- `cat-blog rerender`（D33、D44），`cat-blog backup`（D40，设计文档 §10.3）。
- `Dockerfile`、`deploy/docker-compose.yml`、`deploy/Caddyfile`、`deploy/cat-blog.service`、`.env.example`。
- `README.md`：构建、配置、部署、备份与恢复、升级（升级后需要时执行 `rerender`）。

**完成条件**：`backup` 的集成测试——服务写入数据的同时执行备份，副本通过 `integrity_check` 且能被新进程打开；目标文件已存在时报错；副本权限为 600。

### 阶段 6：验收

按 §5 逐项检查，结果记录在 PR 描述或 `docs/v1.0-acceptance.md`（可否决）中。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| sqlx 编译期宏把查询绑定在 SQLite 上，\"为 Postgres 留路\"实际要重写迁移和全部查询（设计文档 §12） | SQL 只放在 `db` 模块；不用 SQLite 专有功能；迁移时按 §12 的清单评估工作量 |
| `.sqlx/` 和迁移不同步，CI 编译失败或查询类型过期 | `scripts/check.sh` 里跑 `cargo sqlx prepare --workspace --check`（conventions §5.1） |
| comrak 或 ammonia 升级后输出变化 | 依赖锁定在 `Cargo.lock`；升级后跑快照测试，再执行 `rerender` |
| slug 写回破坏作者的 YAML 格式 | 只改一行，且写回后再解析一遍确认 slug 一致，不一致就保存失败 |
| syntect 加载语法和主题较慢、二进制变大 | 启动时加载一次；只启用默认语法集，不额外打包 |
| 时区数据库过期 | `jiff` 随依赖升级更新；Docker 镜像不依赖系统 tzdata（可否决） |
