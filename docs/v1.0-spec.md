## 1. 目标与范围

目标、与 Bear Blog 的关系、范围（D20、D21）都不变，见 [v1.0-design.md](v1.0-design.md) §1–§2。

v1.0 是一个单人自部署的博客程序：一个可执行文件 `cat-blog`、一个 SQLite 文件，HTTPS 由前面的 Caddy 或 Nginx 处理。管理员在 `/admin/` 用一个纯文本框编辑首页、页面和文章（YAML front matter 加 Markdown 正文）。

## 2. 对 D1–D38 的修订

| 原决定 | 问题 | 修订 |
|---|---|---|
| D22「备份只需复制数据库文件」 | 程序运行时，SQLite（WAL 模式）可能还有数据只在 `-wal` 文件里，直接复制主文件会得到不完整的副本。 | 改为用 `cat-blog backup` 命令备份，见 D40。 |
| §5「原文按作者输入原样保存」 | 和 D32「手写的 slug 规范化后写回 front matter」矛盾。 | 原文原样保存，只有两处例外：slug 那一行会被写回（D39），换行统一为 LF（D70）。 |
| D2「sqlx 同时支持 Postgres，为 SaaS 迁移留路」 | sqlx 的编译期宏会把查询绑定到 SQLite，换数据库并不是改个连接串就行。 | 保留 D2 和 D30 的选择，但"留路"的实际含义改为 §12 写的那样。 |
| D15 会话有效期 30 天 | 没说是固定期限还是随使用顺延。 | 固定 30 天，见 D49。 |
| §5 数据模型 | 缺 CSRF token 的存放位置，缺 `description` 列，时间和标签的存储类型未定。 | 用 §6 的表结构替换。 |

## 4. 系统结构

```
浏览器 ──HTTPS──▶ Caddy / Nginx ──HTTP──▶ cat-blog（axum，127.0.0.1:3000）──▶ SQLite 文件
```

- **crates/core**（D25）：纯函数，不依赖 Web 和数据库。负责 front matter 解析、slug、日期、标签、可见性规则、Markdown 渲染、HTML 清洗、`{{ posts }}` 占位、slug 写回。
- **crates/server**：配置、数据库访问（集中在一个 `db` 模块）、认证、路由、模板、命令行。
- 渲染发生在保存时（D33）。请求时只做两件事：判断可见性，以及展开 `{{ posts }}` 占位。

### 4.1 启动流程

1. 读取 `.env` 和环境变量，校验配置：`ADMIN_PASSWORD` 少于 12 个字符时拒绝启动（D14）；`BASE_URL` 必须是 `http(s)://` 开头的合法 URL（末尾的 `/` 会被去掉）；`TRUSTED_PROXIES` 必须能逐项解析为 IP 段，写成空值表示不信任任何代理（不设置时才用默认值）。`BASE_URL` 是 `http://` 时打印警告（D36）。
2. 打开数据库（D72），执行 `migrations/` 中的迁移（D2）。
3. 同步管理员（D14、D66）：表中没有用户就新建；用户名不同就改用户名；用 argon2 校验 `.env` 中的密码和库里的哈希，不匹配就重新哈希。两者只要有一个变了，就清空所有会话。
4. 确保博客存在。第一次启动时写入默认首页和示例草稿（D28）。
5. 删除过期会话（D49）。
6. 开始监听。收到 SIGTERM 或 Ctrl+C 时停止接收新请求，等进行中的请求结束后再退出。

## 5. 内容格式

### 5.1 front matter 的整体规则

- 原文以一行 `---` 开头，下一行单独的 `---` 结束 front matter，后面是 Markdown 正文。首页、页面、文章都必须有 front matter。
- 字段未知、类型不对、YAML 语法错误时，保存失败，原文保留在编辑框里，页面顶部显示错误和**原文中的行号**（D26）。
- 字段值为 `null` 或空时，视同没写。
- 保存前换行统一为 LF（D70）。

**首页字段**（D11）

| 字段 | 类型 | 默认 | 校验 |
|---|---|---|---|
| `title` | 字符串 | `ฅ^•ﻌ•^ฅ` | — |
| `description` | 字符串 | 空 | 用于 `<meta name="description">` 和 RSS 频道描述 |
| `lang` | 字符串 | `zh-CN` | 非空 |
| `timezone` | 字符串 | `Asia/Singapore` | 必须是 IANA 时区名 |
| `nav` | Markdown 字符串 | `[Home](/) [Blog](/blog/)` | 只渲染为行内内容；写了标题、列表、代码块等块级内容时报错。分成几段时，段与段之间用空格连接 |

**页面和文章字段**（§6 原表）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | 字符串 | 是 | 规范化后为空时（比如全是标点）要求手写 `slug` |
| `slug` | 字符串 | 否 | 规则见 §5.3 |
| `date` | 字符串 | 否 | 三种写法见 D43 |
| `draft` | 布尔 | 否，默认 `false` | |
| `tags` | 字符串列表 | 否 | 只有文章可以写（D46） |
| `description` | 字符串 | 否 | 用于 `<meta name="description">` |

新建时的预填模板（D26）：

```yaml
---
title:
draft: true
tags: []
---
```

页面的模板没有 `tags` 一行。

### 5.2 标签

规范化规则见 D46。另外：空字符串报错；单个标签最长 40 字符；`tags: rust` 这种写成单个字符串的写法报错，提示改成 `[rust]`。文章页标题下方显示标签，每个标签链接到 `/blog/?tag=<标签>`。

### 5.3 slug

**规范化**（D32 不变）：NFC 规范化；保留任何语言的字母和数字；ASCII 字母转小写；空格和标点替换为 `-` 并合并；去掉首尾的 `-`。

**保存时如何确定 slug**（D39）：

1. front matter 写了 `slug`：规范化。结果为空、超过 80 字符、和保留路径重名、和同一博客的其他内容冲突时，保存失败（D10）。
2. 没写 `slug`，但这篇内容在库里已经有 slug（作者把那一行删了）：沿用库里的 slug。
3. 没写 `slug`，而且是第一次保存：用 `title` 生成。超过 80 字符时截断到 80 字符，再去掉末尾的 `-`。冲突时报错，不自动改名（D10）。

**写回**：只有当原文里的 slug 和最终结果不一致（包括没写）时，才改写原文，并且只改一行：

- 原文顶层已有单行的 `slug:`：只替换值。
- 没有：在顶层单行的 `title:` 后面插入一行；找不到时，插在结束的 `---` 前面。
- 写回的格式固定为 `slug: "<值>"`。slug 只含字母、数字和 `-`，加引号是为了避免 `2024`、`null` 这类值被 YAML 当成其他类型。
- `slug` 写成多行或其他复杂 YAML 时，保存失败，提示改成单行。

front matter 里的其他行、注释、字段顺序和正文都不动。因为第一次保存后原文里一定有 `slug`，之后改标题不会改 URL；作者手动改 `slug` 才会换地址（旧地址返回 404，D59）。

**保留路径**（D10 补全）：`blog`、`admin`、`static`、`feed.xml`、`sitemap.xml`、`robots.txt`、`favicon.ico`、`healthz`。比较在规范化之后进行。

### 5.4 日期与发布时间

`published_at` 存 UTC 的 Unix 秒（D71），保存时按下面的规则计算：

- 写了 `date`：按 D43 解析，写成未来时间就是定时发布（D12）。
- 没写 `date`，库里已有 `published_at`：保持不变（包括撤回后再发布，D45）。
- 没写 `date`，库里还没有，`draft` 为 `false`：取当前时间。
- 其他情况：保持为空。

**可见性**（`core` 里的纯函数，以当前时间为参数）：`!draft && published_at 不为空 && published_at <= now`。不可见的内容不出现在任何列表、RSS 和 sitemap 中，访问返回 404；已登录的管理员可以直接访问（D12、D68）。

显示日期统一按站点时区格式化为 `2026-11-24`（D34）。

## 6. 数据模型

替换 [v1.0-design.md](v1.0-design.md) §5 的草案。时间都是 UTC 的 Unix 秒（D71），布尔值用 `INTEGER` 0/1。

```sql
CREATE TABLE users (
    id            INTEGER PRIMARY KEY,
    username      TEXT    NOT NULL UNIQUE,
    password_hash TEXT    NOT NULL,              -- argon2id，PHC 字符串（D17）
    created_at    INTEGER NOT NULL,
    updated_at    INTEGER NOT NULL
);

CREATE TABLE sessions (
    id          INTEGER PRIMARY KEY,
    user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token_hash  BLOB    NOT NULL UNIQUE,         -- 会话 token 的 SHA-256（D16）
    csrf_token  TEXT    NOT NULL,                -- D47
    created_at  INTEGER NOT NULL,
    expires_at  INTEGER NOT NULL                 -- created_at + 30 天（D49）
);

CREATE TABLE blogs (
    id          INTEGER PRIMARY KEY,
    user_id     INTEGER NOT NULL REFERENCES users(id),
    home_source TEXT    NOT NULL,                -- 首页原文
    home_html   TEXT    NOT NULL,                -- 首页正文渲染结果（含 posts 占位）
    title       TEXT    NOT NULL,
    description TEXT    NOT NULL,
    lang        TEXT    NOT NULL,
    timezone    TEXT    NOT NULL,
    nav_html    TEXT    NOT NULL,                -- D65
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL
);

CREATE TABLE posts (
    id           INTEGER PRIMARY KEY,
    blog_id      INTEGER NOT NULL REFERENCES blogs(id) ON DELETE CASCADE,
    kind         TEXT    NOT NULL CHECK (kind IN ('page', 'post')),
    slug         TEXT    NOT NULL,               -- 规范化后的值
    source       TEXT    NOT NULL,               -- 原文（含写回的 slug）
    html         TEXT    NOT NULL,               -- 渲染并清洗后的正文（含 posts 占位）
    title        TEXT    NOT NULL,
    description  TEXT    NOT NULL,
    tags         TEXT    NOT NULL DEFAULT '[]',  -- JSON 数组（D46）
    draft        INTEGER NOT NULL,
    published_at INTEGER,                        -- 可为空（§5.4）
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    UNIQUE (blog_id, slug)
);

CREATE INDEX posts_by_kind_date ON posts (blog_id, kind, published_at);
CREATE INDEX sessions_by_expiry ON sessions (expires_at);
```

所有查询都按 `blog_id` 过滤（D6）。会话 token 和 CSRF token 都是 32 字节系统随机数，以 base64url 编码（D19）。

## 7. 渲染

### 7.1 流水线（保存时）

1. 按 §5 解析 front matter，确定 slug，计算 `published_at`。
2. comrak 把正文解析成语法树，开启 GFM 扩展：表格、脚注、任务列表、删除线、自动链接、标题锚点（D4），并开启原始 HTML（D52）。
3. 遍历语法树，把单独成段的 `{{ posts ... }}` 换成一个内部标记（D55）。
4. 用 syntect 适配器渲染为 HTML，高亮输出 CSS class（D51）。
5. ammonia 清洗（D5、D53、D54）。ammonia 默认会删掉所有 HTML 注释，所以清洗后的 HTML 里不可能有作者写的注释。
6. 把第 3 步的内部标记换成 `<!--cat-blog:posts limit=5 tag=rust-->` 这样的注释，存入 `html` 列。因为第 5 步已经删掉了作者写的注释，这类注释只可能来自程序，作者无法伪造。

`cat-blog rerender` 对所有内容重跑这条流水线（D33、D44），但不改原文。如果某篇原文在新规则下解析失败，跳过它、打印原因，并以非零状态码退出。

补充（可否决）：`rerender` 先处理首页，再按首页的时区处理页面和文章。它也不改 slug 和 `updated_at`：新规则下算出的 slug 和库里的不同时，按失败处理（跳过并报告），因为改 slug 就是改地址（D59）。写入时只在库里的原文和 slug 仍是读出时的值时才写，这样服务运行期间后台刚保存的内容不会被旧原文的渲染结果覆盖。

### 7.2 清洗白名单

在 ammonia 默认配置上做这些改动：

- 通用属性加 `id`、`class`、`aria-hidden`、`aria-label`（标题锚点和脚注会用到；v1.0 只有管理员一个作者；以后做 SaaS 时改为只允许特定 class，见 §12）。
- 加入 `details`、`summary`、`section`（脚注列表）、`input`、`iframe`。
- `input` 只允许 `type="checkbox"`、`checked`，并强制带上 `disabled`；`type` 不是 `checkbox` 的 `input` 整个删掉。
- `iframe` 只允许 `src`、`width`、`height`、`allowfullscreen`、`title`；`src` 不在 D54 白名单里时删掉整个元素。保留的 iframe 里面的内容一律删掉（浏览器本来就不显示它，留着会让作者在里面藏注释伪造 posts 占位）。
- 链接保留 ammonia 默认加的 `rel="noopener noreferrer"`。

### 7.3 `{{ posts }}` 指令

语法：`{{ posts }}`、`{{ posts limit:5 }}`、`{{ posts tag:rust limit:5 }}`。参数顺序不限；`limit` 为正整数；`tag` 按 D46 规范化。出现未知参数或格式错误时，保存失败。

首页、页面、文章里都可以写（文章里写也不报错）。请求时把占位注释展开为和 `/blog/` 一样的列表：只列可见的文章，每行显示日期和标题（D37）。RSS 里的占位直接删掉。

## 8. 公开站点

### 8.1 路由

| 路径 | 内容 |
|---|---|
| `/` | 首页正文（不另显示 h1，页头已有站点标题） |
| `/blog/` | 所有可见文章，按 `published_at` 倒序，不分页（D37） |
| `/blog/?tag=x` | 带该标签的文章；标签不存在时返回空列表，不返回 404 |
| `/{slug}/` | 页面：标题和正文。文章：标题、日期、标签和正文 |
| `/feed.xml` | RSS 2.0，最近 20 篇可见文章（D20、D57、D75） |
| `/sitemap.xml` | 首页、`/blog/`、所有可见页面和文章，`lastmod` 取 `updated_at` |
| `/robots.txt` | `Disallow: /admin/`，并给出 sitemap 地址 |
| `/static/*` | 嵌入二进制的资源（D60），地址带内容哈希参数，长期缓存 |
| `/favicon.ico` | 返回 SVG favicon（D61） |
| `/healthz` | D64 |

### 8.2 地址规范化（D58）

- 请求路径先做百分号解码，再做 NFC 和小写规范化，然后查库（D32）。
- 找到内容，但请求的原始写法和规范 slug 不同（大小写不同、Unicode 规范形式不同、缺少尾斜杠），就 301 跳到规范地址。`%E6%88%91` 和直接写 `我` 解码后相同，不算不同。
- `/blog`、`/admin` 同样 301 到带尾斜杠的地址。
- 程序生成的链接、RSS 和 sitemap 中的地址，对 slug 做百分号编码，加上 `BASE_URL` 就是绝对地址。

### 8.3 RSS

频道标题和描述取首页的 `title`、`description`。每篇文章的 `<description>` 是全文 HTML，地址改成绝对地址（D57）：生成 RSS 时用同一份 ammonia 配置再清洗一遍，打开"相对地址按基准地址改写"，基准地址是这篇文章自己的绝对地址，这样 `#fn-1` 这类页内锚点也指向原文。

### 8.4 外观

D27、D31 不变。代码高亮 CSS 的暗色部分同时写在 `[data-theme="dark"]` 下和 `prefers-color-scheme: dark` 媒体查询里，所以禁用 JS 时也跟随系统。

## 9. 后台

### 9.1 路由

| 方法与路径 | 作用 |
|---|---|
| `GET /admin/login`、`POST /admin/login` | 登录（D15、D47、D48） |
| `POST /admin/logout` | 删除当前会话（D16） |
| `GET /admin/`、`POST /admin/` | 编辑首页 |
| `GET /admin/pages/`、`GET /admin/posts/` | 列表（D26），按 `published_at` 倒序，未发布的草稿排在最前 |
| `GET /admin/pages/new`、`GET /admin/posts/new` | 新建（预填模板） |
| `POST /admin/pages/new`、`POST /admin/posts/new` | 第一次保存 |
| `GET /admin/edit/{id}`、`POST /admin/edit/{id}` | 编辑与保存 |
| `GET /admin/delete/{id}`、`POST /admin/delete/{id}` | 确认页与删除（D76） |
| `POST /admin/preview` | 预览（D56），渲染为公开页面的样子 |

未登录访问 `/admin/` 下除登录页以外的地址，303 跳转到 `/admin/login`。后台的 GET 请求不改任何数据，所有 POST 都校验 CSRF（D47）。

### 9.2 编辑与保存

- 编辑页是一个 `<form>`，"保存"提交到当前地址；"预览"用 `formaction="/admin/preview"` 和 `formtarget="_blank"` 提交同一个文本框，不需要 JS。
- 保存成功后 303 跳回编辑页，并显示"已保存"（用 `?saved=1` 参数，不需要会话里的临时消息）。写回了 slug 时，编辑框里看到的就是写回后的原文。
- 保存失败时返回 422，编辑框保留提交的原文，顶部显示错误和行号。slug 和其他内容冲突（D10）时，行号指向原文里的 `slug:` 行，没写 `slug` 时指向 `title:` 行。
- 少量原生 JS（D3）：Ctrl/⌘+S 提交保存；文本框有改动时，离开页面前提醒。
- 同一篇内容在两个标签页同时编辑时，后保存的覆盖先保存的；v1.0 不做冲突检测。

### 9.3 登录

- 错误提示统一为"用户名或密码错误"。用户名不对时也做一次 argon2 校验，避免通过响应时间判断用户名是否正确。
- 会话 cookie 名为 `cat_blog_session`，`Path=/`（公开页面需要据此判断管理员能否预览草稿），属性见 D15、D36。
- 状态码（补充，可否决）：用户名或密码错误时返回 422，重新显示登录表单并保留用户名；`Origin`/`Referer` 校验不通过返回 403；被限流返回 429（D48）。后台 POST 缺少 `_csrf` 或不匹配时返回 403。已登录时打开登录页，303 跳到 `/admin/`。
- 限流计数（补充，可否决）：每次尝试在校验密码之前就先记一次失败，登录成功后清空该 IP 的记录（D48）。这样同一 IP 并发提交的尝试也不会超过 5 次。
- 客户端 IP（补充 D38，可否决）：`X-Forwarded-For` 里的地址全部可信时，取最左边的地址。

## 10. 部署与运维

### 10.1 配置

[v1.0-design.md](v1.0-design.md) §4 的表不变，加一项：

| 变量 | 必需 | 默认值 | 说明 |
|---|---|---|---|
| `RUST_LOG` | 否 | `info` | 日志级别（D63） |

### 10.2 部署文件（`deploy/`）

- `Dockerfile` 放在仓库根目录。多阶段构建，运行镜像以非 root 用户运行；数据目录 `/data` 作为卷；镜像内默认 `DATABASE_PATH=/data/cat-blog.db`、`BIND_ADDR=0.0.0.0:3000`。
- `deploy/docker-compose.yml`：cat-blog 加 Caddy 两个服务。cat-blog 服务的镜像名为 `cat-blog:latest`（补充，可否决）：本机已有这个镜像时 `docker compose up -d` 直接用它，没有时先尝试拉取、失败后从源码构建；`--build` 总是重新构建。cat-blog 不对宿主机暴露端口，只有 Caddy 能访问；`TRUSTED_PROXIES=172.16.0.0/12`（D38）。compose 网络的网段固定为 `172.28.0.0/16`（补充，可否决）：Docker 自动分配的网段不一定落在 `172.16.0.0/12` 里，落在外面时 Caddy 不被信任，所有访客按 Caddy 的地址一起被限流。
- `deploy/Caddyfile`：反向代理到 `cat-blog:3000`。补充（可否决）：站点地址取 `BASE_URL`；compose 读 `deploy/.env`，只把 `BASE_URL` 传给 Caddy，管理员密码不进 Caddy 容器。
- `deploy/cat-blog.service`：systemd 服务文件（非 Docker 部署时用）。
- `.env.example` 放在仓库根目录。Docker 部署时复制为 `deploy/.env`（补充，可否决）。

### 10.3 备份与恢复（D40）

```sh
cat-blog backup /path/to/cat-blog-2026-11-24.db
# Docker：
docker compose exec cat-blog cat-blog backup /data/backups/cat-blog-2026-11-24.db
```

- 执行 `VACUUM INTO '<目标文件>'`，得到一份一致、紧凑的单文件副本，不需要附带 `-wal`、`-shm` 文件。服务运行时可以执行，不需要停机。
- 目标文件已存在时报错，不覆盖。完成后对副本执行 `PRAGMA integrity_check`，结果不是 `ok` 时以非零状态码退出。
- 副本里有密码哈希和会话哈希，命令把副本的权限设为 600。
- 恢复：停止服务，用副本替换数据库文件，删除旧的 `-wal`、`-shm` 文件，再启动服务。
- 补充（可否决）：`rerender` 和 `backup` 只打开已有的数据库，`DATABASE_PATH` 指向的文件不存在时报错，不新建空库。`backup` 的目标目录不存在时以权限 700 自动创建（umask 只会收紧，不会放宽）；先以权限 600 新建空的目标文件再写入，副本在任何时刻都不会被其他用户读到。

### 10.4 发布（D42）

不做自动发布。版本号写在 `Cargo.toml` 里；v1.0 完成（D41）后，手动打 `v1.0.0` 标签（可否决）。部署者用 `docker build` 或 `cargo build --release` 自行构建。

补充（可否决）：内存小的服务器（如 2 GB）上编译 Rust 容易内存不足，可以在另一台机器上构建镜像，用 `docker save` 导出、拷到服务器上 `docker load`。镜像只在部署者自己的机器之间传，不推送到镜像仓库，仍符合 D42。

## 11. 安全小结

| 威胁 | 措施 |
|---|---|
| 正文里的 XSS | 保存时 ammonia 白名单清洗（D5、§7.2）；RSS 再清洗一遍 |
| CSRF | 后台 POST 校验 token；登录页校验 Origin（D47）；cookie `SameSite=Lax` |
| 暴力破解 | 按 IP 限流（D48），IP 的解析见 D38 |
| 会话被盗 | `HttpOnly`、HTTPS 下加 `Secure`；库里只存哈希；固定 30 天（D49） |
| 点击劫持 | 后台加 `X-Frame-Options: DENY`（D74） |
| 草稿泄露 | 不可见内容返回 404，管理员查看时加 `noindex` 和 `no-store`（D68） |
| 备份泄露 | 副本权限 600（§10.3） |

## 12. 风险：sqlx 编译期宏把查询绑定在 SQLite 上

D2 写的是"sqlx 同时支持 Postgres，为 SaaS 迁移留路"，D30 又要求启用离线模式、把 `.sqlx/` 提交到仓库。两者合起来，实际情况是：

- `query!` / `query_as!` 在编译时连接（或读取 `.sqlx/` 中缓存的）**SQLite** 数据库来检查 SQL 和推断类型。生成的代码绑定到 `Sqlite` 驱动，同一段宏代码不能拿去连 Postgres。sqlx 用来同时支持多种数据库的 `Any` 驱动不支持这些编译期宏。
- 查询文本本身也是 SQLite 方言：占位符是 `?`（Postgres 是 `$1`）；标签筛选用 SQLite 的 `json_each`（Postgres 要改成 `jsonb` 操作符或关联表）；布尔值存成 `INTEGER`；`VACUUM INTO` 只有 SQLite 有。
- `migrations/` 里的建表语句也是 SQLite 方言（`INTEGER PRIMARY KEY` 自增、类型亲和性等）。

所以"留路"指的是**数据模型和边界留好了**，不是"改个连接串就能换"。换 Postgres 时要做：重写迁移、改写 `db` 模块里的全部查询、重新生成 `.sqlx/`、把备份命令换成 `pg_dump` 一类工具，并且要写一个数据导出导入脚本。

v1.0 为降低这部分成本做的事：

- 所有 SQL 只写在 `crates/server` 的 `db` 模块里，其他代码只调用这里的函数，不碰 SQL。
- 所有查询都带 `blog_id`（D6）。时间存整数（D71），JSON 只用于标签这一处。
- 不用触发器、视图、FTS 等 SQLite 专有功能。

不建议为了"可移植"改用运行时查询（`sqlx::query`）而放弃编译期检查：对 v1.0 来说，编译期检查带来的好处更实在，迁移时的重写量也不大（预计几十条查询）。这一点同样可以否决。
